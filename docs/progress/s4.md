## API registry (stabilne, zmiany tylko addytywne; łamiące -> docs/proposals/s4-*.md)
Features ładowane automatycznie: `src/features/<nazwa>/index.ts(x)` (import.meta.glob), rejestracja przy imporcie.
- `registerScreen({id,label,icon,order,component,dock?})` — ekran w docku (dock:false = tylko z kodu). Nawigacja: `navigate(id)`, `back()`, `useRoute()` z `core/router`.
- `registerWidget({id,label,size,sizes?,component:(props:{size})=>JSX,opens?})` — kafel Home; domyślny układ `DEFAULT_HOME_LAYOUT` = speed, nav, job, lights, cruise, media (id nieznane pomijane); układ użytkownika w localStorage.
- `registerAlertPresenter(code, alert => ToastContent)`, `registerEventPresenter(kind, event => ToastContent|null)` — treść toastów (S5). ToastContent: title, body?, icon?, level?, duration? (0 = trwały).
- `registerStatusItem({id, side:left|center|right, order, component})` — elementy status bara.
- Dane: `useFastValue(selector, cb)` (rAF, bez re-renderu), `useSlow/useConfig/useStatus/useAlerts/useFast`, `usePending`, `sendCmd`/hold z `core/commands`, `useSettings(selector?)`/`getSettings()` (jednostki: `s.units`).
- S6 (media): zarejestrować ekran `media` + widget `media` (id zgodne z DEFAULT_HOME_LAYOUT); nie dotykać shell/.

## M4
- **Edytor układu Home** (`shell/Home.tsx`, `shell/homeLayout.ts`): long-press kafla (`GlassCard.onLongPress`, 450 ms) → tryb edycji: drżenie (`prefers-reduced-motion` → ramka), przycisk × (usuń), „Dodaj” (Sheet z widgetów registry spoza układu), „Gotowe”. Przeciąganie pointer events (bez bibliotek): duch kafla, reorder na żywo przez `dropOnId` / `dropOnPageEnd`, przytrzymanie przy krawędzi (64 px, 550 ms) przewraca stronę → przenoszenie między stronami. Palec po long-pressie można od razu przeciągać.
- Zapis: `localStorage` `yoga-auto.home.v2` = `{v:2, ids}`; migracja z v1 (goła tablica) przy odczycie; uszkodzone dane → układ domyślny. Reset: Ustawienia → „Przywróć domyślny” (`resetLayout`, kasuje v1 i v2 → `DEFAULT_HOME_LAYOUT` + reszta widgetów).
- Nie zrobione (świadomie): zmiana rozmiaru kafla (`WidgetDef.sizes`) i pusta „nowa strona” jako cel upuszczenia; pakowanie first-fit sprawia, że kafel trafia na stronę wg kolejności, nie wg miejsca upuszczenia.
- **Tryb nocny wg `game.time`** (`core/daynight.ts`, `shell/appearance.ts`): motyw `jasny / ciemny / auto (gra)`. Auto: noc 20:00–6:00 z histerezą ±20 min (wejście 20:00, wyjście 6:20) → ciemny + `night`, dzień → jasny; bez połączenia z grą stan się nie zmienia. Ręczny motyw i przełącznik „Tryb nocny” działają jak dotąd. Przejście płynne: cross-fade całej strony (View Transitions API; fallback/reduced-motion → natychmiast). Czas kwantyzowany do 5 min, żeby nie renderować Appu co minutę.
- **Ekran `map`**: bez zmian w shellu — dock i router czytają `getScreens()`, więc ekran pojawi się, gdy `features/map` wywoła `registerScreen({id:"map", ...})`.
- Testy: `core/test/homeLayout.test.ts` (zapis/migracja/reset, operacje edytora, pagination), `core/test/daynight.test.ts`.
- Zweryfikowane na mocku `city-night` (22:38 → ciemny+noc; wymuszone 12:00 → jasny; 19:50 → bez zmiany; 20:05 → noc) oraz syntetycznymi pointer events: long-press, drag, usuń, dodaj, gotowe, przeniesienie między stronami. Nie testowane na prawdziwym dotyku Yogi.
