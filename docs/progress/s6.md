# Postęp S6 (media)

## Zrobione
- Spike S6-0: PowerShell/WinRT zamiast `windows-smtc-monitor` (bez zależności, bez kompilacji). Wyniki: `integrations/media/SPIKE.md`.
- `integrations/media`: `bin/smtc.ps1` (helper JSON-lines), `helper-protocol.ts` (parser + mapowanie `MediaState`),
  `smtc.ts` (`SmtcMediaProvider`: auto-restart z backoffem, komendy z ack/timeout, cache okładek), `factory.ts`
  (`AutoMediaProvider`/`createMediaProvider`: SMTC → fallback `NullMediaProvider`, `start()` nie rzuca),
  `mock.ts` (Mock: 4 utwory, okładki SVG przez `getArt`), `README.md`.
- UI `apps/yoga/src/features/media/`: widget `media` 2×1 (id z `DEFAULT_HOME_LAYOUT`), ekran `media` (okładka jako rozmyte tło,
  przyciski 72 px, pasek z seekiem, pozycja interpolowana od odebrania stanu), mini-kontrolka w StatusBar (`registerStatusItem`),
  stany „Nic nie gra” i „Moduł mediów wyłączony”.
- Testy: `integrations/media/src/smtc.test.ts` (23), `apps/yoga/src/features/media/helpers.test.ts` (7).
- Przepływ MockMediaProvider → bridge (7429) → WS → UI (Vite 5177) sprawdzony w przeglądarce: widget, ekran, next/pauza
  zmieniają stan, okładka SVG ładuje się z `/media/art/mockN.jpg`. Serwery zatrzymane.
- Propozycje: `docs/proposals/s6-bridge-wiring.md` (podpięcie `createMediaProvider` w `main.ts`),
  `docs/proposals/s6-snapshot-media.md` (keyframe `snapshot` zeruje `media` w store; w feature jest obejście).

## Zostało / niezweryfikowane
- Helper zmierzony na żywo tylko na sesji Chrome (odczyt tytułu/artysty/pozycji). Spotify nie był uruchomiony: okładka, odczyt
  Spotify i DoD „<1 s po zmianie utworu” czekają na test na PC ze Spotify. Komend nie wysyłano do prawdziwego odtwarzacza.
- Po merge'u propozycji S2/S4: wpiąć provider w bridge, uprościć `useMediaInfo` do `useMedia()`.
- Pierwsze ładowanie po starcie Vite raz pokazało „Nic nie gra” (przyczyna: keyframe snapshot, patrz propozycja) — po obejściu nie powtórzone.
